# Чистая установка r22 после удаления r21

Путь предназначен для OpenWrt 25.12.6 `aarch64_cortex-a53`. Он сохраняет старый YAML и весь старый state отдельно, без его принятия или автоматического запуска в новой установке. Ниже — инструкция владельцу; на рабочем роутере она в рамках разработки не исполнялась. До удаления сохраните нужный YAML вне роутера обычной загрузкой из редактора или защищённой копией.

Повторная установка поверх `/etc/xkeenwrt` сохраняет Remove fence. Resume для другого Build ID по-прежнему запрещён; `--finalize-remove` прежнего helper завершает его удаление, а не разрешает Resume. Для чистой установки используется отдельный проверенный recovery ELF из **того же r22**, что и APK.

1. Заранее скопируйте проверенный архив r22 на устройство и сверьте `SHA256SUMS`. Поместите `cleanup/xkeenwrt-recovery-r22` в отдельный root-owned каталог `/tmp/xkeenwrt-r22-clean` с mode 0700; сам ELF также 0700. Он должен находиться вне `/tmp/xkeenwrt` и вне APK payload. До окончания очистки **не устанавливайте r22 APK**: post-install запускает панель/runtime/recovery, хотя не запускает Mihomo и LAN-перехват.
2. Через UI выполните полный Stop и дождитесь остановленного Mihomo и выключенного перехвата. Затем удалите только два пакета проекта. Сетевые инструменты `nft`, `ip-full`, `ubus` и их зависимости должны остаться установленными: они необходимы persistent rescue и финальной проверке. Не используйте автоматическое удаление зависимостей.

```sh
apk --no-network --repositories-file /dev/null del xkeenwrt-ui xkeenwrt-core
/etc/xkeenwrt/rescue/xkeenwrt-recovery --remove-status
```

Продолжайте только при точном `kind: remove`, `state: cleanup_complete`; запишите `request_id` из этого ответа. Не заменяйте его произвольным UUID и не удаляйте journal/fence вручную.

3. Запустите прежний persistent helper с точным `request_id` из шага 2, затем отдельный r22 ELF с тем же значением:

```sh
/etc/xkeenwrt/rescue/xkeenwrt-recovery --finalize-remove <request_id>
/tmp/xkeenwrt-r22-clean/xkeenwrt-recovery-r22 --archive-finalized-remove <request_id>
```

Каждая команда должна завершиться с exit 0. При ошибке остановитесь и сохраните ограниченный текст ошибки: неизвестное владение, недоступность инструментов, незавершённая очистка, занятый cgroup или сохранившаяся служба не обходятся удалением файлов.

Вторая команда берёт lifecycle locks, требует отсутствия пакетного payload и всех его init entry points, удалённых procd definitions (включая respawn), пустых собственных cgroups, отозванного grant и отсутствия сетевых объектов по точному disabled journal либо первоначальному never-enabled состоянию. Она переносит **весь** `/etc/xkeenwrt` в `/etc/xkeenwrt-retired-<request_id>` через `RENAME_NOREPLACE` и fsync `/etc`. YAML, history, journal и Remove fence сохраняются вместе с прежним owner. Собственные ephemeral каталоги архивируются только рядом с прежним местом; данные через разные filesystems не перемещаются. Повтор со старым request не может архивировать новую установку.

4. После exit 0 установите проверенную пару APK r22 обычной командой установки из release. Панель открывается автоматически после package hook. Новый state имеет нового owner и пустой профиль; core/перехват не запускаются установкой. Старый каталог не импортируется. Если старый YAML нужен снова, откройте его копию отдельно и явно импортируйте через UI, затем заново проверьте, примените и выберите входы.

Каталог `xkeenwrt-retired-*` содержит пользовательские секреты и не является отчётом. Сохраните его защищённую копию вне устройства при необходимости. Он не нужен новой активной установке и не подлежит автоматическому удалению или активации.

## Откат 0.1.26.3 → 0.1.26.2

После Stop журнал `/etc/xkeenwrt/recovery.json` хранит манифест последнего поколения. Если шлюз последний раз запускали через Tailscale, в манифесте есть поле `management_channel: "tailscale"` ([решение 024](decisions/024-tailscale-start.md)). Rescue 0.1.26.2 читает журнал со строгой схемой и такое поле отвергнет. Хуком 0.1.26.3 откат не запретить: при установке 0.1.26.2 apk выполняет скрипты 0.1.26.2.

Поэтому откат на 0.1.26.2 — только одним из двух путей:

- чистая переустановка по шагам выше (удаление, `--finalize-remove`, архив прежнего `/etc/xkeenwrt`);
- или сначала запуск из основной LAN и Stop: тогда последний манифест без поля канала и 0.1.26.2 его прочтёт.

Установщик `install.sh` понижение версии не выполняет: он обновляет только с точной предыдущей пары.
