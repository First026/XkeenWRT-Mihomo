# 0.1.26.2: лабораторная приёмка С1–С4 в ARM64 VM

18 ноября 2026. Кандидат `0.1.26.2-r0`, Build ID `8a1de3d1c384b0153856baa3d95e8bdce11ef1da646f7714de7515db3ee49247` ([сборка и хеши](../arm64-current-build.md)). Рабочие роутеры не использовались.

## Стенд

Одноразовая VM OpenWrt 25.12.6 `r33311-981c978eff` `armsr/armv8`, ядро 6.12.112, QEMU 8.2.2 TCG, `cortex-a53`, 1 ГиБ RAM; хост — сборочная VM. Сценарии и подготовка — [`tests/lab/r26.2`](../../tests/lab/r26.2/README.md), основа — стенд [r26](2026-11-17-r26-lab-acceptance.md): закреплённые образы rootfs и ядра GHCR, подписанные индексы и пакеты OpenWrt, `br-lan` 192.168.5.1/24 с LAN-клиентом 192.168.5.2 в netns, WAN 10.0.0.1, пир 10.0.0.3 с upstream DNS, Mihomo 1.19.34 по закреплённому пути.

**Добавлено.**
- **Tailscale-вход.** `tailscale0` — veth с адресом 100.64.10.1; в netns `xk-ts` — администратор 100.64.20.2 (адреса синтетические). Сеть `tailscale` в зоне `lan`.
- **Два «сайта» за WAN-пиром.** `www.gstatic.com` → 1.2.3.4:443 (HTTPS с лабораторным CA) доступен только через Shadowsocks-прокси 10.0.0.3:8388: прямой трафик к нему пир отбрасывает. 1.2.3.5:80 — обычный сайт, доступен напрямую. Каждый обслуживает свой процесс, поэтому остановка прокси не выключает прямой сайт.
- **Профиль:** узел `lab-ss`, правила `DOMAIN-SUFFIX,gstatic.com,lab-ss` и `MATCH,DIRECT`.

**Пакеты.** Пара 0.1-r26 — копия владельца с SHA-256 из прежнего релиза (`8e92b27f…`, `e569a475…`); релиз r26 больше не публикуется. Пара 0.1.26.2 и `xkeenwrt-install-r26.2.run` — кандидат выше.

## Результаты

**Итог: С1–С4 пройдены**, один прогон на чистом диске: `setup` → С1 → С2 → С3 → С4. Serial-лог (322 строки, `level=error` и паник ядра нет) сохранён вне Git: `lab-evidence-r26.2/serial-2026-11-18.log`, SHA-256 `0d67ee5e94911566c4787a59e68277cec96899527771880b10d97ee11ae27171`.

| Сценарий | Итог | Что увидели |
|---|---|---|
| С1 | PASS | Установщик r26 → профиль, Apply, ▶ из LAN, LAN-клиент через шлюз, Stop. `.run` 0.1.26.2: «обновлён с 0.1-r26 до 0.1.26.2-r0», оба пакета `0.1.26.2-r0`, `owner-id` и ревизия профиля прежние, Mihomo `verified`, ссылки журнала целы, recovery жив. ▶ из LAN работает; в журнале нет поля канала управления |
| С2 | PASS | Вся LAN через шлюз: сайт из правила `DOMAIN-SUFFIX` открылся через прокси (`HTTP_404` лабораторного сервера), остальное по `MATCH,DIRECT` — напрямую (`HTTP_401`). Прокси остановлен: первый сайт пропал, второй открывается. После Stop своих nft-объектов нет |
| С3 | PASS | Из LAN: новая ревизия и «Применить» на работающем шлюзе заменили поколение (4 → 5) без `PROFILE_REQUIRED`, LAN-клиент работает; «Перезапустить» — LAN-клиент работает; Stop, ссылки журнала целы |
| С4 | PASS | Через Tailscale: панель открывается (`tailscale_admin`), в совместимости блокер `NETWORK_MANAGEMENT`; ▶ отклонён с `NETWORK_MANAGEMENT` без перехвата; при шлюзе, запущенном из LAN, «Перезапустить» отклонён с `UNSUPPORTED` и шлюз не тронут; Stop через Tailscale работает |

**Первый прогон** на том же кандидате: `setup`, С1, С3 и С4 прошли; С2 упал на шаге «прокси остановлен»: прямой сайт обслуживал тот же процесс, что и прокси, и пропал вместе с ним. Это ошибка стенда, не продукта; сайт вынесен в отдельный процесс, все сценарии повторены с нуля.

## Чего это не доказывает

- Это не настоящий роутер: другой target, veth вместо портов, Wi‑Fi и настоящего Tailscale нет, эмуляция TCG.
- «Интернет» и CA лабораторные; реальные подписки и сторонние службы роутера (zapret2, tgws) проверяются только на устройстве.
