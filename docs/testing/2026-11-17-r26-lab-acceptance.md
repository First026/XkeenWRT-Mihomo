# r26: лабораторная приёмка С1–С3 в ARM64 VM

17 ноября 2026. Кандидат `0.1-r26`, Build ID `fed66f1c82d35b9fbc49d018a06e6ee004541e6170096786e95736d95d459999`, исходники — коммит `20a0cb4`. Проверка по ТЗ r26, раздел 7. Рабочие роутеры не использовались.

## Стенд

Одноразовая VM OpenWrt 25.12.6 `r33311-981c978eff` `armsr/armv8`, ядро 6.12.112, QEMU 8.2 TCG, `cortex-a53`, 1 ГиБ RAM. Гость без сети. Сценарии и подготовка — [`tests/lab/r26-native`](../../tests/lab/r26-native/README.md).

**Образы.** rootfs и ядро — закреплённые образы GHCR, те же, что в `tests/lab/openwrt-vm/Dockerfile.arm64`. SHA-256 ядра проверяется.

**Зависимости.** Пакеты OpenWrt и подписанные индексы `packages.adb` скачаны с downloads.openwrt.org; гость проверяет подпись индексов и каждый пакет при установке:
- `ip-full` с двумя библиотеками;
- kmod: `nft-tproxy`, `nf-tproxy`, `nft-socket`, `nf-socket`, `nf-conntrack-netlink`, `veth`;
- `curl` с двумя библиотеками для сценария.

**Сеть.**
- `br-lan` 192.168.5.1/24; управляющий клиент 192.168.5.2 в netns, подключён к мосту через veth.
- WAN 10.0.0.1 с пиром 10.0.0.3, на пире — upstream dnsmasq.
- Панель отвечает только этому LAN-клиенту, без пароля, как на роутере.

**Пакеты.** Пара r25 — из релиза GitHub (SHA-256 сверены). Пара r26 — кандидат выше.

**Mihomo 1.19.34.** Бинарник положен по закреплённому пути `/usr/libexec/xkeenwrt/cores/1.19.34/mihomo` (SHA-256 `022da41e…`) и выбран через `POST /api/core/update` без загрузки; каталог подтвердил `integrity=verified`.

**Сценарий.** HTTP-шаги — те же, что у панели: сохранить профиль → Validate → Apply → `POST /api/control start` → `GET /api/network/status` → `POST /api/network/confirm` → ожидание `active` → Stop.

## Найдено и исправлено в ходе приёмки

Первый прогон С3 на кандидате `b40e7ab6…` показал, что recovery корректно уходит в Direct, но следующий ▶ навсегда получает `STORAGE_ERROR`. Причина: архивация закрытого журнала проверяла все его снимки, в том числе удалённый.

Исправление `bd0d851`: журнал `RollbackDirect` больше не требует пригодности своих снимков при архивации, остальные снимки проверяются как прежде. Подробнее — в [решении 023](../decisions/023-history-reservation-and-admission.md). После исправления С1–С3 повторены на новом кандидате с нуля, скриптами из репозитория.

## Чего это не доказывает

- Это не настоящий роутер: другой target (`armsr` вместо `mediatek/filogic`), veth вместо портов и Wi‑Fi, эмуляция TCG.
- Прохождение реального клиентского трафика через Mihomo и аппаратный flow offload не проверялись.
- Числа памяти VM не переносятся на устройство. Учёт памяти своего core покрыт unit-тестами, нехватка памяти в VM не моделировалась.
- Негативный контроль — С3 на r25 с циклом падений — не прогонялся: поведение r25 известно из отчёта 17.11 с рабочего роутера.
- Установщик принимает только целевую прошивку: для С4 в VM на время запуска выставлялись метки `mediatek/filogic`/`aarch64_cortex-a53`, затем возвращались.
