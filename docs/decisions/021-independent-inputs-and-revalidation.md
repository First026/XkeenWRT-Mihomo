# 021. Независимые входы одного Mihomo и свежий допуск firewall

15 ноября 2026. Реализация r21 уточняет ADR 007/019/020. Цель — OpenWrt 25.12.6, ARM64 `aarch64_cortex-a53`; рабочие роутеры не используются.

Ядро, явный HTTP/SOCKS и прозрачный шлюз имеют разные состояния. Composite overlay содержит выбранные входы одного Mihomo. HTTP/SOCKS использует mixed 7890, шлюз — TPROXY 7893 и DNS 1053. Исходный YAML не может открыть эти входы. HTTP/SOCKS по умолчанию выключен; пользователь выбирает конкретные адрес и интерфейс административного LAN, подтверждённые kernel/netifd inventory. Guest/WAN не становятся доверенными при обращении к LAN-адресу роутера.

До разрешения запуска listener устанавливается отдельная `inet xkeenwrt_explicit` input-защита: допускаются выбранные LAN ingress, источник из подтверждённой LAN-подсети и выбранный локальный destination; остальные TCP/UDP обращения к mixed port отбрасываются. Состояние защиты хранит точные old/proposed manifests до атомарной nft-транзакции. Чужая таблица с тем же именем не присваивается. Стабильная проверка не пишет flash. Эта таблица отделена от capture; выключение шлюза её не удаляет. Полная остановка сначала снимает capture, затем закрывает собственные входы и ядро.

Explicit-only переключение имеет отдельный durable intent с exact previous/target core snapshots и previous/target selection. Runtime держит общий mutation lock до commit либо восстановления. Независимый rescue, получив lock после незавершённого переключения, возвращает предыдущий снимок и выбор; при изменении boot-id ядро остаётся остановленным. Snapshot references защищены от pruning. В сетевой транзакции explicit входит в previous/current/baseline snapshots. Предлагаемый новый baseline становится authoritative только при Confirm.

Save сохраняет draft. Apply проверяет точную revision, staged providers и настоящий изолированный `mihomo -t`. Остановленный шлюз от Apply не включается. При активном шлюзе Apply — новая READY/Pending/Confirm транзакция с прежними owner/generation, fence и сроком 120 секунд. Принятие base profile имеет intent, решение которого — ровно confirmed network tx; восстановление завершает либо отбрасывает его без произвольного запуска ядра. Успех ядра сам по себе не подтверждает шлюз.

Classifier теперь общий для runtime и независимого rescue. Terminal return допускается только после доказанного address/interface-scoped same-register OR. NAT по mark требует доказать ранние источники нужных битов, порядок prerouting, ingress-покрытие, адресный scope, TCP-порты и отсутствие других writers. Local DNAT проверяется по точным адресам kernel inventory, а не private-подсети или JSON-флагу. `ct state in invalid` допускается только вместе с ICMP time-exceeded; общий drop/TPROXY/unknown write остаётся конфликтом. Уже перенаправленный NAT-трафик обходит owned capture.

Evidence v2 выпускается только после свежего семантического обхода foreign ruleset и проверки свободного выделенного mark. Для него изменение диагностического nft fingerprint не означает автоматический отказ: сравниваются остальные trusted facts, а новый ruleset заново проходит classifier. Address sets могут обновляться; interface sets проверяются на каждом проходе, поэтому включение LAN в бывшую WAN-ветвь не становится совместимым. Legacy evidence сохраняет строгое сравнение. Совместимый reload позволяет сохранить/восстановить exact owned capture. Unsafe drift переводит в direct, снимая только own capture/routes; управление и безопасный выбранный explicit сохраняются. Исчезновение собственной таблицы проверяется отдельно.

Диагностика содержит безопасные table/chain/hook, priority, hash ID правила, вид конфликта и затронутый класс трафика. Адреса, URI, содержимое providers, ключи и технический controller secret в неё не включаются. Host/Origin и административный LAN контроль всех HTTP endpoints сохраняются; нового пароля или токена UI нет.

Нативные результаты и ограничения реальных stgws/nfqws2/Tailscale/REALITY фиксируются отдельно. Наличие fixture, собранного APK или зарегистрированной NFQUEUE не считается packet acceptance.

Commit decision профиля хранится как typed `profile_acceptance` в той же атомарной записи network journal, что и Confirmed. Он сохраняется при последующих Disable/boot/lifecycle cleanup; восстановление manual intent сверяет tx/profile/revision/key/source candidate и при необходимости читает exact pinned archive. Неподтверждённый Pending после boot не принимает новый профиль. `network_commit` ack находится в той же атомарной записи, что и выбранные входы: owner actions сначала завершают принятый commit и сохраняют ack при своём новом выборе. Исторический network journal не может заново включить явно выключенный режим.

Если при отмене replacement предыдущая foreign topology больше небезопасна, helper доказывает отсутствие capture/routes обоих поколений, снимает также прежний failblock, восстанавливает baseline explicit и пишет отдельный terminal `RollbackDirect` receipt. Previous manifests остаются историей; inactive gateway допускает новый Start после устранения конфликта. Это отличается от успешного восстановления previous-good capture.

«Выключить перехват» во время Pending фиксирует `cancel_capture` и revoke до ответа. Helper возвращает terminal direct с baseline explicit, включая отмену replacement, без краткого повторного включения прежнего capture. Это действие получает helper receipt/cancellation и ожидает inactive; Confirm к нему не применяется. Выключение HTTP/SOCKS доступно и при degraded; остановленное ядро от такого выключения не запускается.

Native-проверка выявила lazy `cache.db` у настоящего Mihomo 1.19.34 даже при отключённом сохранении селекторов. Этот файл не входит в профиль, provider snapshot и историю. `core-run` устанавливает umask 077; live proof допускает только необязательный `cache.db` как обычный root-файл 0600, nlink=1, не более 16 MiB, открытый с O_NOFOLLOW, в каталоге 0700. Его появление между readdir и stat допустимо; все остальные имена и immutable bytes остаются точными. Только удаление доказанно собственного retired home допускает legacy cache 0644.

Панель имеет дополнительный узкий IPv4 listener для настоящего `tailscale0`. Он создаётся только для единственного фактического локального адреса 100.64.0.0/10 и явной UCI-сети `tailscale` в однозначной admin-zone `lan` с input ACCEPT. Пересечение с WAN/guest, второй alias устройства и неоднозначные адреса закрывают этот вход. Listener привязан и к адресу, и к устройству; Host/Origin остаются точными. При каждом запросе повторно проверяется текущее назначение адреса и admin-zone; watcher закрывает устаревший listener. Оба listener используют общие лимиты запросов и менеджер обновления ядра.

Через Tailscale доступны панель, status, безопасный полный Stop и отключение перехвата. Включение входов, Restart выбранных входов и Apply активного шлюза требуют настоящего peer основной IPv4 LAN; адрес не подменяется. Restart проверяет эту границу до остановки ядра, UI сообщает ограничение. Эта граница не меняет SSH/uhttpd, которыми распоряжается OpenWrt.

Занятые фиксированные gateway-порты диагностируются только из валидного kernel socket inventory: typed `ResourceConflict` сообщает номер 7893/1053 и TCP/UDP, без адреса или PID. API возвращает `NETWORK_PORT_CONFLICT`, UI показывает ограниченное сообщение; остальные ошибки inventory остаются отдельным отказом.

`ReconcileRequested` при небезопасной новой топологии имеет durable `Direct` outcome, который сохраняет строгие journal/snapshot bindings и допускает последующий owner Disable. Завершённый Direct не порождает новые записи на каждом health cycle: для стабильности требуются доказанное отсутствие own nft/routes и свежий отказ `verify_restore`. Ошибки ownership и частичные остатки не считаются стабильным direct. После совместимого изменения topology восстановление capture снова допускается.
