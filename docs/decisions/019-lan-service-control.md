# 019. Обычный Start управляет всей LAN

15.11.2026. Уточнение владельца: «Вставил подписку и михомо проксирует все устройства по правилам». Это заменяет ограничение раннего пилота одним выбранным клиентом. Рабочие роутеры по-прежнему не используются для разработки и испытаний.

Основной сценарий: импорт подписки → сохранение и проверка точного профиля → Apply → Start. Save не запускает ядро. Start использует принятый снимок с загруженными providers, определяет LAN через netifd и включает Mihomo вместе с перехватом всей IPv4-подсети LAN. Статические адреса и новые DHCP-клиенты не требуют добавления в список. Интернет-трафик административного клиента также обрабатывается по YAML. Локальные назначения, управление самим роутером и исходящие соединения самого Mihomo исключаются из перехвата.

`lan_scope` хранит точную каноническую подсеть, подтверждённую адресами интерфейса. HTTP не выбирает диапазон. В этой версии поддерживается одна IPv4-подсеть штатного LAN; гостевые/VLAN-сети не добавляются автоматически. Внешний IPv6 блокируется во время перехвата, локальный IPv6 и ND сохраняются. Это ограничение явно показано в панели. Политика отказа обычного Start — direct_on_failure.

Start выполняет прежнюю сетевую транзакцию с READY, привязкой owner/generation, доказательствами nft/routes и таймером 120 секунд. Отдельной пользовательской формы Plan/Confirm больше нет. После ответа Start браузер делает новый запрос состояния по административному пути и подтверждает именно эту транзакцию. Confirm повторно проверяет ядро, правила, маршруты, срок и fence. Потеря связи до этого запроса оставляет откат включённым. Для обычного Start это заменяет требование отдельного клика Confirm в ADR 002; восстановление и ограничения владения не ослабляются.

Stop сначала запрашивает снятие перехвата через recovery. При Pending он сохраняет отзыв транзакции. Успех отображается только после отсутствия собственных сетевых объектов и остановки ядра. Restart последовательно выполняет Stop и Start. Системные network/dhcp/firewall и чужие службы не переписываются. Конфликт с другим перехватчиком остаётся явной ошибкой.

Старые журналы без `lan_scope` сохраняют прежнюю семантику одного клиента и читаются без миграции. Новый диапазон участвует в доказательстве сетевого состояния и в восстановлении. Пакет UI требует ip-full, kmod-nft-tproxy и kmod-nft-socket из совместимого OpenWrt feed.

Визуальное имя панели: **XkeenWRT**. Рабочий процесс Mihomo сам по себе не считается доказательством включённого перехвата.

Штатный `/tmp/resolv.conf.d/resolv.conf.auto` читается как ограниченный снимок DNS: фиксированный путь, обычный root-owned файл без symlink, не более 64 KiB и восьми числовых nameserver. Runtime и recovery используют один код чтения, список входит в evidence. При noresolv=1 неактивный resolvfile игнорируется. UCI и системные DNS-настройки не изменяются.
