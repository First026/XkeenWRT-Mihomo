# 020. Сосуществование с fw4, stgws и zapret2

15 ноября 2026. Владелец поручил исправить NETWORK_FIREWALL_CONFLICT r19 без отключения чужих служб и без подключения к рабочему роутеру.

## Порядок обработки

Новое поколение манифеста `capture_version=1` ставит TPROXY в filter/prerouting с priority **−90**. Сначала работают stgws mark (−149), zapret2 prenat (−101), DNAT и redirect, затем zapret2 prerouting (−99), затем захват оставшегося LAN IPv4. NAT lookup-цепочки упорядочиваются внутри общего DNAT hook ядра −100; поэтому одной прежней priority −151 у DNS было недостаточно для общей совместимости.

Пакеты с `ct status dnat` не захватываются повторно. Это сохраняет уже выполненный redirect/DNAT Telegram TCP 80/443/5222 на 8490. DNS имеет собственный redirect 1053, исключение DNS из TPROXY сохраняется. Вход не с LAN, локальные адреса, подключённые маршруты и исходящий трафик самого ядра не захватываются. Старые журналы без `capture_version` сохраняют прежний AST с priority −150: новая сборка не переинтерпретирует старое доказательство владения.

## Проверка чужих правил

Имя таблицы не является разрешением. Проверяются тип и priority hook, безопасные выражения, ограниченные mark-операции, типизированные redirect/DNAT, разрешённые ICMP time-exceeded drop и каждый достижимый переход. Отдельное доказательство исключения LAN разрешает ветви WAN: уникальный локальный set типа ifname читается из того же снимка. Обход ограничен глубиной и бюджетом. Неизвестный TPROXY, изменение порядка hooks, flow offload, неоднозначный переход и неподдерживаемая mark-операция блокируют Start.

Пустой fw4 helper допускается только при единственном jump в уникальную обычную пустую цепочку той же таблицы. Поддержаны одно имя интерфейса и ограниченный inline set валидных имён; непустая цель не становится разрешённой по имени helper.

Mark-аллокатор резервирует биты, затронутые строго разобранными same-register OR/AND/XOR, и биты маски сравнения meta/ct mark. Полная запись, копирование другого регистра и неизвестная форма по-прежнему резервируют все 32 бита. Tailscale mask из policy rules также учитывается. XkeenWRT назначает свободный бит и не переписывает чужие marks.

## Гонки и диагностика

Plan хранит семантический отпечаток чужого ruleset. Apply повторно сверяет его до сетевой мутации и после запуска ядра. Меняющиеся handles и счётчики исключены; порядок правил и содержимое sets сохранены. READY/Confirm, ownership, дедлайн, recovery и Stop остаются прежним контрактом. Runtime возвращает ограниченную диагностику таблицы, цепочки, hook и класса конфликта; адреса, содержимое sets и конфиги в сообщение не попадают.

## Границы

Перехваченный пакет заканчивает путь на локальном Mihomo: он уже не проходит прежние forward/postrouting как сквозной пакет. Исходящий DIRECT/прокси-транспорт Mihomo проходит действующие output/postrouting, включая zapret2; ответ проходит WAN prenat. Параметры nfqws2 и конфигурация stgws не меняются. Это сохраняет применимые hooks, но не обещает идентичный DPI-эффект каждой стратегии на изменившихся соединениях. Реальные сервисы и репрезентативные правила в отчёте различаются. Рабочие роутеры не используются.
