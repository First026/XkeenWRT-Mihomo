# XkeenWRT 0.1.26.4

XkeenWRT — независимый порт веб-панели [XKeen-UI](https://github.com/zxc-rv/XKeen-UI) от zxc-rv для OpenWrt с движком Mihomo. За основу взят [XKeen-UI v1.4.6](https://github.com/zxc-rv/XKeen-UI/tree/b8ed60c098594c356c0ae871f77fc6598e0a9c8c). В обоих APK сохранены оригинальный текст MIT и `Copyright (c) 2026 zxc-rv`.

## Что нового

- **Обновление из панели.** Нажмите кнопку с версией вверху панели: окно покажет релизы новее установленного, с описанием. Выберите версию и нажмите «Установить» — роутер сам скачает с GitHub и запустит установщик этого релиза, тот же, что в быстром старте, с проверкой SHA-256 обоих APK. Панель перезапустится на новой версии и покажет результат. Перед обновлением нажмите «Остановить», после — «Запустить». Если вышла новая версия, кнопка подсвечивается ([решение 026](https://github.com/First026/XkeenWRT-Mihomo/blob/v0.1.26.4/docs/decisions/026-panel-self-update.md)). Работает начиная с этой версии: до 0.1.26.4 нужно один раз обновиться по SSH, следующие версии ставятся из панели.
- **«Остановить» больше не зависает после разового сбоя.** Если при остановке на миг не удался возврат ядра, отключение раньше оставалось в ошибке: статус «degraded», «Остановить» отвечал «занято», и помогало только «Выключить перехват». Теперь роутер сам повторяет упавший шаг, не больше двух раз, и доводит остановку до конца. Домашняя сеть при этом всё время работает напрямую ([решение 025](https://github.com/First026/XkeenWRT-Mihomo/blob/v0.1.26.4/docs/decisions/025-active-event-retry.md)).
- **Причина сбоя видна в журнале роутера.** Каждый неудачный шаг recovery пишет в `logread` строку `recovery step failed: step=…` с видом ошибки и кодом ОС.
- Всё остальное — как в 0.1.26.3: запуск, перезапуск и «Применить» через Tailscale с проверкой DNS и выхода на самом роутере; HTTP/SOCKS — только из домашней сети.
- Откат на старую версию из панели не предусмотрен — только по SSH.

## Обновление

[Быстрый старт одной командой по SSH](https://github.com/First026/XkeenWRT-Mihomo#быстрый-старт) — чистая установка или обновление с 0.1.26.3. Перед обновлением нажмите в панели **Остановить**. Формат журнала не менялся: записи 0.1.26.4 читает и rescue 0.1.26.3.

## Проверка

Проверено в одноразовой ARM64 VM OpenWrt 25.12.6 (`armsr/armv8`, QEMU), не на устройстве. Сценарии:

- обновление с 0.1.26.3 установщиком `.run`;
- все сценарии 0.1.26.3: правила профиля, Tailscale, отказы при недоступном прокси и DNS, «Применить» и «Перезапустить»;
- новый С8: остановка после внесённого сбоя возврата ядра. Роутер сам повторил шаг и завершил остановку, причина записана в `logread`;
- новый С9: обновление из панели через Tailscale на лабораторную версию 0.1.26.4.1 с лабораторной копии GitHub. Панель предложила только более новую версию и отказала при работающем шлюзе; установщик обновил пару, панель перезапустилась и сообщила результат; профиль и Mihomo сохранились.
