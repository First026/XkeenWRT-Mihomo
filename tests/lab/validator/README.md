# Лабораторная изоляция нативного валидатора

Этот самостоятельный однопоточный эксперимент на Rust выполняет фиксированные синтетические сценарии внутри маркированной OpenWrt VM на x86-64 или AArch64. Он не связан с production backend и не принимает произвольные команды, пути или профили пользователей. Обычный запуск на хосте завершается отказом до внесения изменений. Не запускайте его с привилегиями на машине разработки или рабочем роутере.

Supervisor допускает дочерний процесс в проверенную cgroup, создаёт приватные namespaces и ограниченное хранилище, сбрасывает привилегии, устанавливает seccomp до exec и контролирует ограниченный вывод и время. Перед сообщением об успехе он завершает всё задание и проверяет очистку. Probe и закреплённый Mihomo используют один путь запуска.

Фиксированные случаи охватывают проверки файловой системы, FD, окружения и привилегий, запрет сокетов, лимиты байтов и inode tmpfs, лимиты процессов, исчерпание памяти, таймаут с отсоединённым потомком, чрезмерный вывод и отказ до запуска полезной нагрузки. Случаи Mihomo охватывают корректный и некорректный YAML, отсутствующую MMDB, размещённый внутри изоляции синтетический ключ SSH и недоступную цель его внешней символической ссылки, а также принятие парсером AmneziaWG v3/legacy. Регрессионная проверка нечитаемой некорректной конфигурации должна отказать в валидации; одного нормального выхода с кодом 1 недостаточно для подтверждения отказа разбора YAML. PEM fixture — намеренно открытый синтетический тестовый ключ, который никогда не используется для реальной учётной записи или соединения.

Из корня репозитория при наличии закреплённого toolchain, кешированных зависимостей и проверенного архива core:

```sh
./tests/lab/openwrt-vm/build.sh --isolation
./tests/lab/openwrt-vm/isolation.py
```

Для полной ARM64 VM используются отдельные закреплённые ядро и rootfs `armsr/armv8`, архив ARM64 Mihomo и target `aarch64-unknown-linux-musl`:

```sh
./tests/lab/openwrt-vm/build.sh --arm64
./tests/lab/openwrt-vm/isolation.py --arm64
./tests/lab/openwrt-vm/isolation.py --arm64 --test-guard
```

Проверка отказа на непривилегированном хосте:

```sh
./tests/lab/validator/tests/host-refusal.sh tests/lab/validator/target/x86_64-unknown-linux-musl/release/isolation-lab
```

Контракт приведён в [решении 006](../../../docs/decisions/006-validator-lab-supervisor.md), измеренные результаты и точные идентификаторы артефактов — в отчётах для x86 и для ARM64. Политики seccomp, фиксированные fixtures и защита стенда экспериментальны. Работа на физическом роутере, размещение произвольных ресурсов, восстановление после сбоя самого supervisor, production-интеграция, активация и восстановление сети этим crate не подтверждены. Пиковые значения cgroup не являются общими требованиями к RAM и не доказывают, что нагрузка поместится на роутере.
