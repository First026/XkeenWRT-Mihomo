# Стенд приёмки 0.1.26.4 (С1–С9)

Одноразовая VM OpenWrt 25.12.6 `armsr/armv8` под QEMU TCG; хост — сборочная VM, рабочие роутеры не используются. Основа — стенд [r26](../r26-native/README.md): те же образы, `init`, `boot.sh`, `console.py`. Это стенд [0.1.26.3](../r26.3/README.md) со сдвинутыми версиями (старая пара — 0.1.26.3 из релиза `v0.1.26.3`) и новыми сценариями: С8 для [решения 025](../../../docs/decisions/025-active-event-retry.md) и С9 для [решения 026](../../../docs/decisions/026-panel-self-update.md).

Добавлено к r26:
- **Tailscale-вход.** `tailscale0` — veth; в netns `xk-ts` стоит администратор в tailnet 100.64.20.2, роутер — 100.64.10.1 (адреса синтетические, из 100.64.0.0/10). Сеть `tailscale` (proto none, device `tailscale0`) в зоне `lan`. Панель открывает на этом адресе свой узкий listener.
- **Лабораторный «интернет».** На WAN-пире: DNS отдаёт `www.gstatic.com` → 1.2.3.4 (адрес «публичный»: защита dnsmasq от rebinding отбрасывает частные и тестовые сети); там HTTPS (второй Mihomo с лабораторным CA, CA добавлен в бандл гостя) и Shadowsocks на 10.0.0.3:8388. Прямой трафик LAN к 1.2.3.4 пир отбрасывает, поэтому этот сайт открывается у LAN-клиента только через прокси. Второй сайт, 1.2.3.5:80, доступен напрямую и живёт в отдельном процессе.
- **Лабораторный GitHub** для С9 (`github.sh`). На пире 1.2.3.6:443 `uhttpd` с сертификатом лабораторного CA отвечает за `api.github.com`, `raw.githubusercontent.com` и `github.com`. Он отдаёт список релизов (0.1.26.3, 0.1.26.4 и лабораторный 0.1.26.4.1), `install.sh` версии 0.1.26.4.1 и её APK. Пара 0.1.26.4.1 — то же дерево, собранное с версией `0.1.26.4.1-r0`; она не публикуется. Её `install.sh` — `install.sh` дерева с этой версией, предыдущей версией 0.1.26.4 и SHA-256 лабораторных APK.
- **Профиль с правилами:** узел `lab-ss`, `DOMAIN-SUFFIX,gstatic.com,lab-ss` и `MATCH,DIRECT`. Пробу выхода роутер ведёт через `lab-ss` на `https://www.gstatic.com/generate_204`.

Порядок:
1. `./prepare.sh <каталог с парой 0.1.26.3> <каталог с 0.1.26.4> <mihomo-linux-arm64-v1.19.34.gz> <каталог с лабораторной 0.1.26.4.1>` — образы GHCR, подписанные индексы и пакеты OpenWrt, пара 0.1.26.3 из релиза `v0.1.26.3` (SHA-256 сверяются), пара 0.1.26.4 и `.run`, лабораторный CA и лабораторный GitHub.
2. `XK_LAB=… ../r26-native/boot.sh &`, затем через `console.py`: `setup.sh`, `c1.sh` (на чистом диске: 0.1.26.3 → 0.1.26.4 установщиком), `c2.sh` … `c9.sh` по порядку.

| Сценарий | Что проверяет |
|---|---|
| С1 | Обновление 0.1.26.3 → 0.1.26.4 установщиком `.run`: профиль, Mihomo и owner сохраняются; ▶ из LAN работает, в журнале нет поля канала |
| С2 | Из LAN вся сеть через шлюз по правилам: сайт из правила — через прокси, остальное — напрямую; без прокси пропадает только первый |
| С3 | ▶ через Tailscale: пробы DNS и выхода, канал в журнале и статусе, LAN-клиент ходит по правилам |
| С4 | Прокси недоступен → `NETWORK_REMOTE_EGRESS`, снятие перехвата, своих nft-объектов нет, прямой сайт открывается |
| С5 | Upstream DNS недоступен → `NETWORK_REMOTE_DNS`, снятие перехвата |
| С6 | Через Tailscale: «Применить» на работающем шлюзе, «Перезапустить», отказ HTTP/SOCKS и пилотного плана, Stop |
| С7 | Из LAN после Tailscale-поколений: ▶, «Применить» на работающем шлюзе, «Перезапустить», Stop; поле канала не записывается |
| С8 | Разовый сбой возврата ядра при Stop: каталог ядра на миг небезопасен, событие отключения получает `RECOVERY`, recovery сам повторяет шаг и завершает отключение; Stop проходит, `logread` называет упавший шаг |
| С9 | Обновление из панели через Tailscale: каталог предлагает только 0.1.26.4.1; отказы при работающем шлюзе, для старых и неизвестных версий; установщик релиза во временном сервисе procd обновляет пару, панель перезапускается и сообщает результат; owner, профиль и Mihomo сохранены, ▶ из LAN работает на 0.1.26.4.1 |

Правка файла в работающем госте: `./put.py $XK_LAB/serial.sock ЛОКАЛЬНЫЙ_ФАЙЛ ПУТЬ_В_ГОСТЕ` — без base64 (его нет в busybox гостя), файл подменяется только при совпадении SHA-256.

Отклонения от устройства: `armsr/armv8`, veth вместо портов, Wi‑Fi и настоящего Tailscale (DERP и WireGuard не моделируются), лабораторный CA, «интернет» и GitHub (без перенаправления загрузок на `objects.githubusercontent.com`). Вход в панель стенд не использует, поэтому повторный вход после перезапуска панели в С9 не проверяется.
