# Стенд приёмки 0.1.26.3 (С1–С7)

Одноразовая VM OpenWrt 25.12.6 `armsr/armv8` под QEMU TCG; хост — сборочная VM, рабочие роутеры не используются. Основа — стенд [r26](../r26-native/README.md): те же образы, `init`, `boot.sh`, `console.py`. Стенд объединяет [стенд 0.1.26.2](../r26.2/README.md) (правила профиля) и Tailscale-сценарии стенда 0.1.26.1.

Добавлено к r26:
- **Tailscale-вход.** `tailscale0` — veth; в netns `xk-ts` стоит администратор в tailnet 100.64.20.2, роутер — 100.64.10.1 (адреса синтетические, из 100.64.0.0/10). Сеть `tailscale` (proto none, device `tailscale0`) в зоне `lan`. Панель открывает на этом адресе свой узкий listener.
- **Лабораторный «интернет».** На WAN-пире: DNS отдаёт `www.gstatic.com` → 1.2.3.4 (адрес «публичный»: защита dnsmasq от rebinding отбрасывает частные и тестовые сети); там HTTPS (второй Mihomo с лабораторным CA, CA добавлен в бандл гостя) и Shadowsocks на 10.0.0.3:8388. Прямой трафик LAN к 1.2.3.4 пир отбрасывает, поэтому этот сайт открывается у LAN-клиента только через прокси. Второй сайт, 1.2.3.5:80, доступен напрямую и живёт в отдельном процессе.
- **Профиль с правилами:** узел `lab-ss`, `DOMAIN-SUFFIX,gstatic.com,lab-ss` и `MATCH,DIRECT`. Пробу выхода роутер ведёт через `lab-ss` на `https://www.gstatic.com/generate_204`.

Порядок:
1. `./prepare.sh <каталог с парой 0.1.26.2> <каталог с 0.1.26.3> <mihomo-linux-arm64-v1.19.34.gz>` — образы GHCR, подписанные индексы и пакеты OpenWrt, пара 0.1.26.2 из релиза `v0.1.26.2` (SHA-256 сверяются), пара 0.1.26.3 и `.run`, лабораторный CA.
2. `XK_LAB=… ../r26-native/boot.sh &`, затем через `console.py`: `setup.sh`, `c1.sh` (на чистом диске: 0.1.26.2 → 0.1.26.3 установщиком), `c2.sh` … `c7.sh` по порядку.

| Сценарий | Что проверяет |
|---|---|
| С1 | Обновление 0.1.26.2 → 0.1.26.3 установщиком `.run`: профиль, Mihomo и owner сохраняются; ▶ из LAN работает, в журнале нет поля канала |
| С2 | Из LAN вся сеть через шлюз по правилам: сайт из правила — через прокси, остальное — напрямую; без прокси пропадает только первый |
| С3 | ▶ через Tailscale: пробы DNS и выхода, канал в журнале и статусе, LAN-клиент ходит по правилам |
| С4 | Прокси недоступен → `NETWORK_REMOTE_EGRESS`, снятие перехвата, своих nft-объектов нет, прямой сайт открывается |
| С5 | Upstream DNS недоступен → `NETWORK_REMOTE_DNS`, снятие перехвата |
| С6 | Через Tailscale: «Применить» на работающем шлюзе, «Перезапустить», отказ HTTP/SOCKS и пилотного плана, Stop |
| С7 | Из LAN после Tailscale-поколений: ▶, «Применить» на работающем шлюзе, «Перезапустить», Stop; поле канала не записывается |

Правка файла в работающем госте: `./put.py $XK_LAB/serial.sock ЛОКАЛЬНЫЙ_ФАЙЛ ПУТЬ_В_ГОСТЕ` — без base64 (его нет в busybox гостя), файл подменяется только при совпадении SHA-256.

Отклонения от устройства: `armsr/armv8`, veth вместо портов, Wi‑Fi и настоящего Tailscale (DERP и WireGuard не моделируются), лабораторный CA и «интернет».
